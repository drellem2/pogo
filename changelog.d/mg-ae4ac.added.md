- **enth tags and release branches (mg-ae4ac, enth-vcs §8, slice 12).** On an enth repo, `Refs.Tag` is `enth tag` and `Refs.CreateRef` is `enth ref create`. Both have an idempotent retry: a `tag_exists`/`ref_exists` at the Change asked for is success. A tag or branch at anything else is refused and never moved. New: `pogo refinery ref-create <ref> --repo=… [--at=<rev>]` (`POST /refinery/ref-create`) creates a release branch through the seam. On git it runs `--auto-create-target`'s steps. With no `--at` it branches from the default branch, which is `--auto-create-target`'s form on enth. `pogo land --post-merge-tag=<tag>` (in the template: `self_land --post-merge-tag=<tag>`) tags what a self-land landed as, before the item closes. A failed tag leaves the item open, mails the coordinator, and exits 6. A `--branch release/<name>` spawn is now accepted on an enth repo, and every other non-trunk `--branch` is still the slice-9 409. Git is unchanged: 384 of 384 git template renders are byte-identical, and the git ref-create and spawn controls dispatch as before.
