- **`pogo check-stranded` finds enth work by its `Pogo-Item` trailer (mg-28cbc, enth-vcs slice 6b).** On an enth-backed repo (a project record with `"vcs": "enth"`) the sweep lists every unlanded Change through enthd (`enth changes --unlanded`) and joins each one's `Pogo-Item` trailer to the item's status. Unlanded work on an open item with no running worker is `stranded`, and so is unlanded work on a **done** item: the item closed without its work landing. On git a branch outlives its item and the worktree scan can find it; on enth the trailer listing is the only place that work shows up. The remedy is `pogo refinery submit --item=<id>`. When the item's Changes form several stacks it is the listing instead, because submit refuses an ambiguous one. An enth MR already in the queue makes the row `in_flight` (or excludes it when the item is claimed). Archived and shelved items are excluded and counted. An item whose status cannot be read is `unjudged`. A failed listing is a `repo_unreadable` row per open item. Landed Changes are not in the listing, so they are not reported. The coverage line counts the Changes with no trailer. The git sweep's rows are unchanged.
