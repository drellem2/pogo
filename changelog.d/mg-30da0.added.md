- **pogo can find, check and submit a worker's enth work (mg-30da0, enth-vcs slice 6).** On an enth repo a worker's output is its Changes carrying `Pogo-Item`/`Pogo-Worker` trailers, listed through enthd (`enth changes`) and ordered into stacks. **`pogo presubmit --item=<id>`** is the polecat pre-submit check as a verb. On git it is the template's `presubmit_check`, line for line (tested against the template's own shell). On enth it refuses a dirty checkout, a base Change without a `Pogo-Item` trailer (with the remedy), no Changes, several stacks, and a stack whose top is not the checkout's base. **`pogo refinery submit --item=<id>`** takes the item as the identity of the work. On enth the branch is refused, an item with no Changes fails `class=defect`, two workers' stacks are refused naming each worker, and the submitted ids are recorded on the MR (`enth_submitted`). Landing them is slice 7, and until then such an MR fails before any git step. On git `--item` resolves an omitted branch through the item's live polecat; a submit without `--item` is unchanged. An enth polecat now gets an author/committer identity for `enth change` when enth would find none: git's, for the source repo. `--stranded-adopt` works on enth and checks out the item's top unlanded Change. `pogo gc --list-preserved` lists enth checkouts, and `pogo check-stranded` reports a trailer-less base as stranded work.
