- **A one-shot `com.pogo.stampfix` launchd job that clears a foreign VCS stamp,
  breaking the deadlock that had aborted the nightly deploy since 2026-07-29
  (mg-3888).**
  Every deployed binary carried a stamp naming a commit from a *different*
  repository:

      installed pogod: c28e26e28921...  <FOREIGN — no such commit in ~/.pogo/deploy-src>
      installed pogo : c28e26e28921...  <FOREIGN — no such commit in ~/.pogo/deploy-src>

  **The deadlock is an ordering, not a permission.** `cmd_redeploy` calls
  `classify_drift` before it acts, and `classify_drift` returns 1 on a foreign
  stamp — so the redeploy exits at the gate, *before* reaching the `go install`
  that is the only thing which clears that stamp. `--force` and `--skip-drain`
  both act after the gate, which is why neither ever helped.

  The break is to run the `go install` **outside** the script, so that by the
  time `redeploy` runs, the stamp it would have refused is already gone. Nothing
  in `pogo-self-deploy` is patched or bypassed — it is handed a tree it accepts.

  **This was mis-filed as human-only, and that was wrong.** `assert_out_of_band`
  does not require a person; it refuses exactly two callers — a descendant of
  `pogod`, and anything with `POGO_AGENT_NAME` set — and returns 0 for everything
  else. A LaunchAgent is neither, so it passes *by construction* rather than by
  exemption, and it survives the `launchctl kickstart -k` for the same reason:
  launchd owns it, `pogod` does not. An agent authors and installs the job;
  launchd runs it.

  **Two things were measured rather than assumed.**

  - **Why `go install` alone is enough to clear the gate.** `foreign_axes`
    iterates *three* axes, including `running pogod` — a live daemon's own
    reported revision, which no rebuild can change. Had that axis been foreign,
    installing first would not have helped and the whole approach would have
    failed at the same gate. It is not: the daemon being replaced predates
    `/version` and 404s it, so `running_rev` yields the `REV_UNREACHABLE`
    sentinel, which `foreign_axes` and `unstamped_axes` both skip. Only the two
    *installed* axes are foreign, and those are exactly what `go install`
    rewrites.
  - **How the stamp got foreign.** A build from a polecat worktree. A worktree's
    `.git` is a *file*, `go build` does not follow it, and it walks up to
    `~/.pogo` and stamps that repo instead:

        $ cd ~/.pogo/polecats/3888 && go build -o /tmp/pogod ./cmd/pogod
        $ go version -m /tmp/pogod | grep vcs.revision
            vcs.revision=e957ced765fd...   # <- ~/.pogo's HEAD
        $ git rev-parse HEAD
        e7d13f0c654b...                    # <- the worktree's actual HEAD

    So the runner asserts `$POGO_DEPLOY_SRC/.git` is a real **directory** and
    refuses on a worktree, rather than trusting the operator not to repeat it.

  **The install and the redeploy are one job, back to back**, because splitting
  them opens the mg-49bc protocol-mismatch window: `go install` rewrites both
  binaries but bounces nothing, so until the restart the on-disk CLI is new while
  the running daemon is old and new subcommands 404 against it. Leaving the
  restart to the 03:00 nightly would hold that window open for hours.

  **Fail-closed, and one-shot.** The fleet is bounced only if the stamp is
  *verifiably* native to `deploy-src` afterwards — a bounce that left the
  deadlock in place would cost the fleet for nothing. The sentinel is written
  *before* the redeploy, not after, because the redeploy takes minutes and a
  second calendar fire landing mid-bounce must not start a second one; the cost
  is that a failed run does not retry itself, which is the safe direction.

  Should the redeploy fail after a successful install, the window is open but not
  indefinitely — and this is the reassuring property of the ordering. Once the
  stamp is cleared the deadlock is broken *permanently*: `classify_drift` stops
  returning 1, so the nightly that had been failing at that exact gate
  reclassifies as `RESTART owed` and finishes the restart on its own.

  Because a one-shot is otherwise a script whose first execution is also its only
  test — and this one's untested half ends in a fleet-wide bounce —
  `POGO_STAMPFIX_DRY_RUN=1` rehearses everything up to the bounce (tool
  resolution, both refusals, the `go install`, the stamp verification) and prints
  the command it would have run. It writes no sentinel, so a rehearsal cannot
  block the real run it was meant to de-risk.
