- **enth self-lands are gated on the MERGED tree (mg-64f2e, pm-enth's 11-04 recipe).** The new standalone `enth-land-gate --job=<name> --gate='<cmd>' <changes>` (`cmd/enth-land-gate`, Apache-2.0, stdlib only, no pogo imports) works in four steps. It runs `enth land --dry-run` to get the tree T the land would produce, hunk-merge included. It reuses a pass already on T. Otherwise it checks out the dry run's result and PROVES it is T: the dry run of that Change must report submitted == landed == itself with tree T, and a moved trunk re-plans instead of testing. Then it runs the gate there and `enth attest`s T. An infrastructure failure (timeout, signal, out of disk, a gate that cannot start, a failed checkout) attests nothing. The `self_land` function in the build and architect polecat templates calls it, then lands with `enth land --require ci/selfland/build`, and an `unattested_tree` (the trunk moved since the gate) gates the new merged tree and lands again, capped. Two Changes that are each green on their own base and broken together are refused, or re-tested to red, and never landed. Each land prints its mode. `GATED`. `TEST-ONLY`: the token cannot attest, which the attest itself probes (`forbidden`); the tree is re-checked by dry run right before the land, and the land runs without `--require`. `GATE NOT INSTALLED — landing untested`: the gate binary or an enth with `land --require` is missing, and the land runs untested as before; the flip to fail-closed is mg-2000f. Needs enth with mg-b729a (`attest`, `land --require`, dry-run `tree`).
