- **An enth project can name its own enth token (mg-3a813).** `pogo project add --vcs=enth --enth-token-file=PATH`, `pogo project set-vcs ... --enth-token-file=PATH`, and `pogo project set-enth-token <path> (--file=PATH | --clear)` for an existing project, record the PATH (never the value) on the project record as `enth.token_file`. pogod reads the file at each use and sets `ENTH_TOKEN` only for that project's polecats and for its own enth calls for that project (polecat checkout, the stranded-work listing, `check-stranded`, `pogo land --item`). pogod's own environment, and so every crew agent's, is unchanged. A named file that cannot be read refuses the spawn (409) or the call, naming the path; it never falls back to pogod's `$ENTH_TOKEN` or the shared `enth login`. A project with no token file keeps today's behaviour, and git records are byte-unchanged. The file is a JSON object with a `"token"` field (a minted enth bot token) or the bare token. Changing only the token file is not a change of backend, so it is not refused while the repo has open work.
