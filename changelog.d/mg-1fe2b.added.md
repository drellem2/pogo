- **The refinery lands enth work (mg-1fe2b, enth-vcs slice 7).** An MR submitted with `pogo refinery submit --item` on an enth repo now lands through the repo's enthd: `enth land --dry-run` gives the tip `T` and the result `N`, the gates run in a fresh checkout of `N`, and `enth land --expect-tip T --expect-new N --request-id <MR>/<attempt>` lands exactly that or nothing — the tree that was gated is the tree that lands. A conflict fails `class=defect` naming each path; `stale_tip` and `result_mismatch` are contention, re-run from the dry run and counted against `max_attempts` (a passed gate is reused while `N` is unchanged). The land is recorded on the MR before it is sent (`enth_pending`), so a land whose answer was lost — including a pogod killed mid-land — is replayed under its original request id instead of being landed twice. The MR records enth's land line as `enth` and leaves `merged_sha` empty. A resubmit resolves `already_merged` only when a merged MR on record for the item lists every submitted Change; `pr_mode` is refused on enth. The git pipeline is unchanged. `scripts/enth_land_test.sh` proves it end to end against a real pogod and enthd.
