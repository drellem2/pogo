- **The stranded-mail suite's fixture registers the mailboxes it invents, and the
  merge queue that this blocked for an evening is on the record (mg-6661).**

  `internal/strandedmail`'s mg-backed tests plant fixture mail at recipient names
  they make up — `aa96`, `waa96`, `wfc99` — and depended on `mg mail send`
  creating a mailbox on first delivery. **mg-d639 removed that side effect**: an
  unknown recipient is now REFUSED (`no_such_mailbox`, exit 3), because the old
  behaviour let a typo'd name mint a dead drop that reported "Delivered".

  From that merge onward the suite failed at its first send:

      --- FAIL: TestAgainstRealMg                                mg_test.go:43
      --- FAIL: TestAgainstRealMgStaysQuietWhenNothingIsStranded  mg_test.go:109
      FAIL  github.com/drellem2/pogo/internal/strandedmail

  **The blast radius is why this has an entry of its own.** That package is in
  `go test ./...` → `test.sh` → `build.sh` → the refinery's quality gate, so the
  gate failed on **every pogo branch**, for a defect none of them introduced, and
  the error text implicated whichever branch was unlucky enough to be in the gate.
  Four MRs were killed by it before the cause was named, and the whole queue
  stopped. A fixture's stale assumption about another repo's CLI is not usually a
  release-note item; one that shuts the queue is.

  The flag itself — `--create` on the fixture's one shared `mgSend` helper, which
  both tests go through — landed in **mg-0155**'s full-gate sweep, which found this
  alongside the sink-harness breakage from the same merge. mg-6661 was the ticket
  opened against it and records the reasoning; the two arrived within half an hour
  of each other and the fix is one line either way.

  **`--create` here is not a retreat from the mg-7dc1 ruling** that it must not
  spread to callsites. At a caller the refusal is real signal that a recipient is
  wrong. This is a fixture builder whose every recipient is unknown *by
  construction* — `TestMain` pins `MG_ROOT` under a throwaway root — and whose
  entire meaning is that those names exist. It is the case the refusal was written
  to leave room for, not a way around it. Nothing in the package's production path
  gains the flag.

  **What was deliberately not done.** The tests were not deleted or skipped.
  `TestAgainstRealMg` shells out to the real `mg` binary because the failure it
  guards against — mg's NDJSON field names drifting under us — is exactly what a
  mock keyed on our own struct tags cannot see. That coupling is what caught this
  cross-repo regression within hours of it merging. Skipping the test to clear the
  gate would have removed the only thing watching.

  `testmain_test.go`'s sandbox rationale is corrected in the same place: it
  justified pinning `MG_ROOT` by asserting that `mg mail send` creates the mailbox
  it is given, which mg-d639 made false. The isolation requirement is unchanged —
  it never rested on sends being harmless — and now rests on the fixture's
  explicit `--create`.
