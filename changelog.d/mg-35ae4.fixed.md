- **pogod's stranded-work alerts now work on an enth repo (mg-35ae4, enth-vcs slice 9b).** The release reporter and the restart sweep asked git about `polecat-<name>`, and an enth project's path is an enth checkout with no `.git`. So for an enth item with unlanded Changes the release logged "could NOT check" and sent nothing, and the sweep counted it unjudged in the log only (measured on a sandboxed enthd). Both now read the item's unlanded Changes from the `enth changes --unlanded` listing that `pogo check-stranded` uses. Landed and superseded (`Pogo-Supersedes`) Changes are not counted. An item with unlanded Changes and no live polecat on it gets a `[stranded-push]` mail and a `work_item_stranded_push` event (`"vcs": "enth"`). The remedy is the self-land path (`enth land … && pogo land --item`), never `pogo refinery submit`. A listing enthd cannot answer still alerts, as `disposition: unjudged`. Unlanded Changes with a live polecat on the item are in flight: they are not reported, and the sweep counts them as `in_flight`. Slice 9's open-refinery-MR check (`CheckOpenMR`, `open_mr`) is removed, because the refinery refuses enth MRs. Git output is byte-unchanged.
